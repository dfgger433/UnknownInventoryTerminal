# 阶段1 本地任务计划

范围：后端 + 游戏内测试前端。阶段2由用户手动进入，本阶段不开展正式 UI 美化。

## 目录与 Git

- 仓库位于 mods/UnknownInventoryTerminal（按上级 AGENTS.md，禁止子目录嵌套 .git）。
- 编译项目和源文件位于 src/；测试位于 tests/；研究位于 research/；交付位于 dist/（忽略生成物）。
- 不修改游戏原版 DLL、其他 mod、备份或存档；部署通过显式脚本执行。

## 实施顺序

1. [完成] 以本机程序集核对 Body / Item / 容器 / 原版 UI、CUCoreLib 设置与输入、Together 的本地角色和交互同步；依据见 [COMPATIBILITY.md](COMPATIBILITY.md)。
2. [完成] 实现稳定实例引用的库存快照、嵌套遍历去重、同类聚合和按容器分组。
3. [完成] 实现搜索 API（外部设置查询及注册额外匹配器）、可选拼音集成；接口见 [SEARCH-API.md](SEARCH-API.md)。
4. [阶段1边界] 测试前端只选择真实实例并在操作前重新校验本地归属；完整原版 UI 菜单/拖拽桥接留阶段2。
5. [完成] CCL 独立设置分类、可配置独立快捷键、最小 IMGUI 测试窗口和游戏输入门。
6. [完成] 构建、自动化测试、接口检查、交付文档与单机/客机实机验收表。

## 验收边界

- 编译与逻辑测试可在当前环境完成；没有进行的游戏交互和双机联机必须标为待实测。
- 合并显示只合计实例数量，不合并真实物品，不复制或重建物品。
- 客机无需主机安装本 mod；复用原版交互入口，使 Together 的既有 Harmony 补丁继续工作。
- 不引入自定义网络消息、不更改联网 mod 的安装和配置。

## 发现

- 当前目录原本为空，发现旧终端的只读源码备份；旧实现使用猜测反射接口、按类型 ID 选实例，不能直接作为本阶段成品。
- 本机有 .NET SDK 10、ilspycmd，目标框架须适配游戏 Unity/Mono，而非直接使用 .NET 10 运行时。
